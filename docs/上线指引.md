# A. 计时修复

## 修了什么

**问题**：浏览器已经杀掉，后台还在继续计时，最长虚记了 1 小时，直到下次打开浏览器才被结算。

**根因**：页面打开不到 60 秒就被杀掉时，前端一次心跳都还没发出，会话的 `duration` 一直是 0。
下次打开页面时，后端走「零心跳兜底」分支，用 `现在 − 开始时间` 的墙钟差补时长（封顶 2 小时），
于是整段间隔全被算成了学习时间。

**修法**：计时只认前端心跳。零心跳 = 没有有效学习，一律记 0。
同时新增 `last_beat_at` 字段和**懒结算**，僵尸会话不必等 Reload 才被清理。

## 服务器落地步骤

### 第 1 步：拉取最新代码

在 PythonAnywhere 的 **Consoles → Bash** 里执行：

```bash
cd ~/zsd-study
git pull origin main
```

> 如果 `git pull` 报冲突，先执行 `git stash` 再拉，拉完 `git stash pop`。

### 第 2 步：清理历史脏数据

先把已经虚记的时间纠回来。**先预览，确认无误再执行**：

```bash
# 预览（不写库，只打印将要修改的记录）
python3 scripts/fix_zombie_sessions.py --db data/study.db --dry-run
```

看清楚输出的每一条，确认都是「墙钟跨度远大于实际时长」的记录后，再执行：

```bash
python3 scripts/fix_zombie_sessions.py --db data/study.db
```

如果历史记录里已经存在被污染成 7200 秒（2 小时）的僵尸会话，加上压缩：

```bash
python3 scripts/fix_zombie_sessions.py --db data/study.db --cap 5
```

> 脚本是幂等的，重复执行不会重复扣减，也不会删除任何记录。

### 第 3 步：Reload Web App

在 PythonAnywhere 的 **Web** 页面点击绿色的 **Reload** 按钮。

> 首次 Reload 时，`sessions` 表会自动加上 `last_beat_at` 字段（老库自动迁移，不用手工建表）。

### 第 4 步：验证

1. 手机上打开网站，进任一课程停留 **10 秒左右**，然后**直接杀掉浏览器**（不要点返回）。
2. 等 5 分钟以上，从家长端进入「学习记录」。
3. 预期结果：**不会**出现「打开 10 秒却记了几十分钟/几小时」的记录。

想验证「正常学习仍能记时」：

1. 手机打开网站，正常做题 **约 3 分钟**（保持页面在前台）。
2. 杀掉浏览器。
3. 家长端「学习记录」应显示 **3 分左右**，起止时间相隔约 3 分钟，而不是一直挂着「学习中」。

## 计时逻辑速查（改后的规则）

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 打开 < 60 秒被杀（零心跳） | 下次打开时按墙钟差补，可能虚记 1 小时 | **记 0** |
| 打开 3 分钟被杀（有 180 秒心跳） | 记 180 秒 | 记 180 秒（不变） |
| 正在学习，1 分钟前刚心跳 | 显示「学习中」 | 显示「学习中」（不变） |
| 连续学习 27 分钟后正常关闭 | 记 1620 秒 | 记 1620 秒（不变） |
| 服务久未 Reload，僵尸会话挂着 | 一直挂到下次打开 | 读学习记录/时长时**自动结算** |

**一句话**：浏览器关了就不会再有心跳，没心跳就不计时。

# B. 跨境链路优化

## 为什么做

实测发现访问慢/不通的根因是**跨境链路**，不是应用故障：

- 境外访问全部正常（HTTP 200、延迟 219ms、0 丢包）
- 网络路径经中国电信骨干 → 国际出口 → 美国 AWS 弗吉尼亚，出口后大量超时
- 三个域名（应用 / 管理页 / 主域）解析到**同一个 IP**，所以「管理页也超时」

同时发现前端两个明显浪费（实测响应头）：

```
Content-Length: 85233
Cache-Control:  no-cache, must-revalidate   ← 每次打开都全量重下
（无 Content-Encoding）                       ← 完全没压缩
```

## 改了什么

| 优化项 | 说明 |
|---|---|
| **gzip 压缩** | HTML/JSON/JS/CSS/SVG 全部压缩，零第三方依赖 |
| **静态页缓存** | `/`、`/admin` 由 `no-cache` 改为 `max-age=600` + ETag 协商 |
| **接口禁缓存** | `/api/*` 保持不缓存（数据实时性），但仍享受压缩 |
| **首屏先绘制** | 初始化推迟到首屏绘制后，避免 52KB JS 阻塞白屏 |
| **登录路径加固** | 登录/注册/匿名原本没有超时和重试，现已补上；超过 4 秒会提示「网络较慢，正在重试…」 |

## 实测效果

| 资源 | 优化前 | 优化后 | 降幅 |
|---|---|---|---|
| 首页 HTML | 85,233 B | **26,348 B** | **-69%** |
| 课程列表 API | 12,694 B | 2,636 B | -79% |
| 课程详情 API | 37,463 B | 8,457 B | -77% |
| **重复访问首页** | 85,233 B | **0 B（304）** | **-100%** |

**预期感受**：
- 首次打开：传输量降到约 1/3，弱网下白屏时间明显缩短
- 日常刷题（高频重访）：命中缓存或 304，**几乎零传输**
- 链路拥塞时：关键操作最多等 12 秒即重试，不再无限转圈

> 注意：这一层是**缓解**不是根治。链路本身波动时（例如你遇到的持续约 5 分钟不通），
> 页面仍可能短暂打不开 —— 但传输量降到 1/3 后，能通过的窗口会明显变多。

## 验证方式（可选）

更新后在手机上打开网站，应该感觉到：
1. 首次打开更快（尤其弱网）
2. 反复打开几乎秒开（走了本地缓存）
3. 网络差的时候会显示「网络较慢，正在重试…」而不是一直转圈
